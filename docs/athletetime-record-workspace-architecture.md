# AthleteTime 기록 작업공간 계약

> 상태: 구현 전 계약 고정
>
> 범위: 선수 기록 검색, 기록 작업공간, 비교, 이 기기에서의 본인 기록 지정
>
> 상위 정책: `athletetime-identity-roi-decision.md`,
> `athletetime-self-claim-record-grouping.md`,
> `athletetime-record-exploration-design.md`

이 문서는 기록 작업공간 개편의 단일 구현 기준이다. 화면, 브라우저 저장소,
공개 API, 주소, 문구가 서로 다른 의미로 바뀌지 않도록 고정한다. 이 문서는
법적 안전을 단정하지 않으며, 기존 정정·숨김·출처 정책을 대체하지 않는다.

## 1. 결정 요약

1. 일반 탐색과 `내 기록`은 화면, 주소, 저장소를 공유하지 않는다.
2. 같은 이름의 공개 프로필을 한 화면에 둘 수는 있지만, 같은 사람이라고
   확정하거나 서버 데이터를 병합하지 않는다.
3. 모든 기록을 다 가진 것처럼 말하지 않는다. 확인된 수, 실제 관찰 연도,
   출처 범위를 함께 보여준다.
4. 기록 숨김, 되돌리기, 비교, 정정 요청은 서로 다른 동작이다.
5. 기록의 원본 행, 전체 출처, 원시 식별자, `person_no`, 생년월일은 새
   브라우저 저장소에 넣지 않는다.

## 2. 네 가지 문맥

| 문맥 | 목적 | 주소 | 저장 | 금지 |
|---|---|---|---|---|
| `browseTarget` | 공개 프로필 하나를 탐색 | `/records/athletes/:athleteKey` | URL과 쿼리 캐시 | `내 기록`으로 표현하거나 self 저장소 변경 |
| `recordWorkspace` | 같은 이름의 공개 프로필을 동일인 확정 없이 함께 검토 | `/records/workspaces/:workspaceId` | 별도 localStorage | 원본·신원 병합, 경력 연속성 단정 |
| `selfClaimDraft` | 이 기기에서 사용자가 고른 비권위적 본인 기록 초안 | `/records/me` | 별도 localStorage | 계정 소유권, 본인 인증, 다른 기기 동기화 표현 |
| `comparison` | 서로 다른 프로필도 포함하는 독립 비교 세션 | `/records/compare/:compareId` | 별도 sessionStorage | 작업공간을 한 사람으로 단정, 우열 판단 |

`selfClaimDraft`는 향후 로그인·본인 확인 기반의 본인 신고 묶음과 다르다.
현재 범위에서 이것은 이 기기 안의 사용자 선택일 뿐이며, 서버에 영구 저장하거나
본인성의 근거로 사용하지 않는다.

## 3. 신원과 소속 표시

### 3.1 athleteKey

- 공개 분석 API가 제공하는 `athleteKey`만 저장한다.
- 내부 원시 식별 조각, `person_no`, 생년월일, 새 동일인 ID를 만들거나 저장하지 않는다.
- 서로 다른 정규화 이름은 하나의 기록 작업공간으로 확정할 수 없다. 비교 흐름으로 보낸다.
- 같은 이름이어도 자동 병합하지 않는다.

### 3.2 소속 문구

| 화면 문맥 | 허용 표현 | 금지 또는 주의 |
|---|---|---|
| 단일 공개 프로필 | `최근 확인 소속`, `이전 확인 소속` | `현 소속` |
| 명시적 self 초안 | `최근 확인 소속`, `이전 확인 소속` | 계정 확인·공식 프로필 암시 |
| 여러 athleteKey 작업공간 | `선택한 기록의 소속`, `다른 기록에서 확인된 소속` | 한 사람의 현재·이전 경력처럼 표시 |
| 같은 마지막 시즌에 소속 복수 | `최근 소속 확인 필요` | 한 곳을 임의로 최신 소속으로 지정 |

여러 `athleteKey` 작업공간의 이름 아래에는 다음 문구를 계속 표시한다.

> 같은 이름의 기록을 함께 보고 있습니다. 같은 사람으로 확인된 것은 아닙니다.

이 문구는 13px 이상, 배경 대비 4.5:1 이상으로 표시하며 색만으로 상태를
전달하지 않는다.

## 4. 기록 범위와 완전성

다음 표현은 사용하지 않는다.

- `전체 기록`
- `완전한 이력`
- `공식 이력`
- `공식 랭킹`

기본 표현은 `AthleteTime에서 확인된 N개`다. API가 아는 공개 결과 수와 지금
화면에 보여 준 수를 분리한다.

| 상황 | 사용자 문구 |
|---|---|
| 일부만 불러옴 | `확인된 124개 중 50개를 먼저 보여드려요` |
| 관찰 연도 | `2019 · 2021 · 2022 · 2024년에 기록이 확인됐어요` |
| 빈 연도 | `2020년은 기록이 확인되지 않았어요` |
| 빈 연도 설명 | `미출전인지 자료 누락인지 구분할 수 없어요` |
| 출처 보류 | `원본을 다시 확인하고 있어요` |

- 연도 범위는 연속된 기간이 아니라 실제 확인된 연도만 쓴다.
- 억제·검토중 기록은 공개 결과, 총계, 오류 문구 어느 곳에서도 존재나 수를
  추론할 수 없어야 한다.
- `qualityState`는 공개 출처 메타데이터의 완성도만 뜻한다. 숨김 상태나
  개인 요청 상태를 뜻하지 않는다.

## 5. 주소와 이동 계약

### 5.1 기본 주소

| 주소 | 역할 |
|---|---|
| `/records` | 검색과 복귀 지점 |
| `/records/athletes/:athleteKey` | 공개 프로필 하나 |
| `/records/me` | 이 기기에서의 self 초안 |
| `/records/workspaces` | 저장한 기록 모음 관리 |
| `/records/workspaces/new` | 선택 후보 검토 |
| `/records/workspaces/:workspaceId` | 확정 작업공간 |
| `/records/compare/:compareId` | 비교 설정과 결과 |

### 5.2 화면 상태 쿼리

| 상태 | 쿼리 |
|---|---|
| 검색 선택 모드 | `/records?mode=collect` |
| 종목 안으로 들어감 | `?event=:eventKey` |
| 기록 상세 Sheet | `&record=:publicRecordId` |
| 비교 설정 또는 결과 | `?stage=setup` 또는 `?stage=result` |

쿼리에는 공개 색인의 불투명 키만 쓴다. 이름, 생년월일, 새 개인정보를 주소에
넣지 않는다. 종목, 상세 Sheet, 비교 단계 전환은 history `PUSH`를 사용한다.

### 5.3 구 주소 호환

| 이전 주소 | 새 주소 | 이동 방식 |
|---|---|---|
| `/records?athlete=:key` | 선수 상세 | `replace` |
| `/athlete/:id` | 선수 상세 | `replace` |
| `/records?compare=a,b` | 로컬 비교 세션 후 비교 주소 | `replace` |
| `/records?flow=mine...` | `/records/me` | `replace` |

- 서버 301/302는 이 범위에 넣지 않는다.
- 호환 이동은 한 번만 실행하며 뒤로 가기 기록을 추가하거나 반복 이동하지 않는다.
- 상세 Sheet가 열린 상태의 뒤로 가기는 Sheet부터 닫는다.
- 종목 화면과 선택 모드의 뒤로 가기는 각각 종목 색인과 평상 모드로 먼저 돌아간다.
- 직접 연 깊은 주소에 이전 방문 기록이 없으면 `/records`로 돌아간다.

## 6. 브라우저 저장소 계약

| 키 | 매체 | 최대 | 저장 내용 |
|---|---|---:|---|
| `athletetime.recordWorkspaceDraft.v1` | sessionStorage | 후보 6개 | 선택 중인 공개 키 |
| `athletetime.recordWorkspaces.v1` | localStorage | 모음 20개 | 공개 키, 공개 라벨 스냅샷, 제외 ID, 필터, 시각 |
| `athletetime.selfClaimDraft.v1` | localStorage | 후보 6개 | 이 기기 self 초안 키 |
| `athletetime.recordComparisons.v1` | sessionStorage | 대상 4명 | setup/ready 상태, 공개 키, 종목, 복귀 주소·초점 |
| `athletetime.recordMigration.v1` | localStorage | 1개 | 이관 상태와 시각 |

### 6.1 저장 규칙

- 작업공간에는 마지막 공개 응답의 표시용 정보만 아래처럼 저장할 수 있다.

```ts
subjectSnapshots: Array<{
  athleteKey: string;
  displayName: string;
  teamLabel: string;
  observedSeasons: number[];
}>;
```

- 이 스냅샷은 이용 불가한 대상을 사용자에게 설명하기 위한 표시용 정보이며,
  신원을 확정하는 정보가 아니다.
- 원본 기록 행, 출처 전체, 비공개 요청 정보는 복제하지 않는다.
- 모든 저장값은 런타임 검증 후 사용한다.
- 손상된 값은 앱 전체를 멈추지 않고 해당 모음의 복구 화면만 연다.
- 20개 한도에서는 오래된 모음을 자동 삭제하지 않는다. 관리 화면에서 정리하도록 안내한다.
- 저장이 막히면 현재 탭의 메모리 상태로 계속 보되 `지금은 이 탭에서만 볼 수 있어요`를 표시한다.

### 6.2 기존 my-athlete 저장소 이관

기존 `athletetime.my-athlete.v1/v2`는 자동으로 self 초안으로 옮기지 않는다.

```text
not_seen
  -> awaiting_choice
  -> writing_new
  -> migration_marked
  -> legacy_deleted
```

1. 첫 `/records/me` 진입에서 `이전에 모은 기록 검토`를 보여 준다.
2. 사용자는 `내 기록으로 지정`, `다른 선수 기록 모음으로 저장`, `모두 비우기` 중 하나를 고른다.
3. 새 저장에 성공하고 migration 완료 표식 저장까지 성공한 뒤에만 구 키를 삭제한다.
4. 어느 쓰기라도 실패하면 `awaiting_choice`로 돌아가고 구 키를 그대로 보존한다.

## 7. 공개 작업공간 미리보기 API

```http
GET /api/card-studio/analytics/record-workspaces/preview
  ?subjectKey=<opaque-key>
  &subjectKey=<opaque-key>
  &cursor=<opaque-cursor>
  &limit=50
```

### 7.1 입력과 정렬

- `subjectKey`: 1~6개, 키 하나 최대 120자
- 중복 키: 첫 항목만 사용
- `limit`: 기본 50, 최대 100
- `cursor`: 마지막 `(date, id)`를 담은 불투명 base64url 값
- 정렬: 날짜 내림차순, 같은 날짜면 안정적 기록 `id` 오름차순

프런트는 반복 쿼리로 키를 보낸다.

```ts
for (const key of subjectKeys) {
  params.append('subjectKey', key);
}
```

응답은 공개 가능한 `subjects`, 다중 키 신원 경고, 관찰 소속, 범위 정보,
종목 색인, 현재 페이지 기록만 포함한다. 범위 정보는 `totalMatched`, `returned`,
`hasMore`, `nextCursor`, 실제 `observedSeasons`, `competitionCount`,
`sourceCount`, `lastCapturedAt`, `qualityState`를 제공한다.

### 7.2 보호와 오류

- 전용 제한: IP당 1분 30회
- `skipAdmin: false`, `noStore: true`
- 기존 억제·삭제 필터와 데이터 권리 고지를 재사용
- 서버에는 작업공간, 비교 대상, 사용자 선택을 영구 저장하지 않음

| 상황 | 응답 |
|---|---|
| 키 없음·형식 오류·7개 이상 | 400 `INVALID_SUBJECT_KEYS` |
| 커서 오류 | 400 `INVALID_CURSOR` |
| limit 오류 | 400 `LIMIT_OUT_OF_RANGE` |
| 모든 키 이용 불가 | 404 `WORKSPACE_NOT_AVAILABLE` |
| 일부 키 이용 불가 | 200과 `unavailableSubjectKeys` |
| 속도 제한 | 429 `RATE_LIMITED` |
| 내부 오류 | 500, 내부 경로·원본 내용 비노출 |

## 8. 편집과 비교의 의미

| 행동 | 결과 |
|---|---|
| `이 모음에서 숨기기` | 현재 기기의 해당 작업공간에서만 기록을 숨김 |
| `되돌리기` | 다음 파괴적 동작 또는 페이지 이탈 전까지 직전 숨김 복구 |
| `다시 모두 보기` | 해당 작업공간의 로컬 제외 목록 초기화 |
| `기록이 틀렸어요` | 기존 정정·숨김 요청 화면으로 이동 |
| `비교` | 별도 설정 단계에서 2~4개 프로필과 공통 종목을 고름 |

- 기록 숨김 선택과 비교 대상 선택은 체크 상태를 공유하지 않는다.
- 숨김 뒤에는 `최근 변경: N개 숨김 · 되돌리기`를 계속 보여 주고
  `aria-live="polite"`로 알린다.
- 비교는 `setup`에서 현재 프로필을 첫 대상으로 넣고 다른 선수를 검색해 추가한다.
  대상이 한 명이면 `비교할 선수를 한 명 더 추가해 주세요`를 보이고 결과 이동은 막는다.
- 두 명 이상이면 공통 종목만 활성화한다. 비교 결과는 우열이나 순위가 아닌,
  같은 종목의 공개 기록을 세로 행으로 나란히 보여 준다.

## 9. 복구와 접근성 문구

| 상황 | 사용자에게 보일 동작 |
|---|---|
| 첫 불러오기 실패 | `다시 불러오기`, `검색으로 돌아가기` |
| 다음 페이지 실패 | 이미 본 기록 유지, `더 불러오지 못했어요 · 다시 시도` |
| 429 | 이미 본 기록·선택 유지, `잠시 후 다시 불러와 주세요` |
| 일부 프로필 이용 불가 | `{이름 · 소속} 기록을 불러오지 못했어요`, `다시 시도`, `이 모음에서 빼기` |
| 저장 차단·용량 부족 | `지금은 이 탭에서만 볼 수 있어요` |
| 손상된 모음 | `복구할 수 없는 모음이에요`, 삭제 또는 검색 재시작 |

- 화면에는 `localStorage`, `UUID`, `cursor`, `volatile` 같은 구현 용어를 쓰지 않는다.
- 선택 제한, 로딩, 오류, 복구 상태는 색과 아이콘만으로 표현하지 않는다.
- 모든 주요 조작은 44x44px 이상이다.
- reduced motion에서는 전환을 즉시 처리한다.

## 10. 구현 전 검증 기준

- [ ] 네 문맥과 다섯 저장 키가 이 문서에 정의되어 있다.
- [ ] 일곱 기본 주소와 네 호환 이동이 정의되어 있다.
- [ ] 단일 프로필의 소속 표현과 다중 키 작업공간의 소속 표현이 분리되어 있다.
- [ ] 다중 키 작업공간의 동일인 미확인 경고가 정의되어 있다.
- [ ] 억제·검토중 기록의 수를 공개하지 않는다고 명시되어 있다.
- [ ] 원시 식별자, `person_no`, 생년월일, 자동 동일인 병합을 요구하지 않는다.
- [ ] `공식 이력`, `공식 랭킹`, `전체 기록`, `완전한 이력`, `현 소속`을
  사용자 문구로 사용하지 않는다.

## 11. 구현 순서

이 계약을 바꾸려면 먼저 이 문서와 관련 정책 문서를 함께 검토한다. 이후 작업은
공개 미리보기 API, 분리 저장소, 공통 UI, 기록 묶음, 후보 검색, 전용 페이지,
