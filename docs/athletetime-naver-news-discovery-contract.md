# 뉴스 발견함 운영 계약

## 목적

NAVER API HUB 뉴스 검색은 육상 소식을 놓치지 않기 위한 관리자용 발견 도구다. 검색 결과는 발행 근거가 아니다. 편집자가 원출처를 다시 확인하고 기존 출처 정책과 인간 승인 절차를 통과해야 매거진 편성에 사용할 수 있다.

## 분리 원칙

- 발견 결과는 `editorial_news_discoveries`에 저장한다.
- 검증된 발행 근거는 기존 `editorial_sources`에 저장한다.
- 발견 결과를 `editorial_sources`로 자동 복사하지 않는다.
- 발견 결과와 검토 메모는 공개 API와 공개 화면에 노출하지 않는다.
- 자동 초안, 자동 승인, 자동 발행을 하지 않는다.

## 저장 범위

저장하는 값은 정제한 제목, 원문 URL, 네이버 검색 링크, 발행 시각, 최초·최근 발견 시각, 고정 검색 프로필 키, 관련성 점수·태그, 검토 상태, 확인한 원출처 URL, 캘린더 연결 ID다.

기사 description, 기사 본문, 원문 HTML, API 원본 응답, cookie, 인증 헤더, API 키, 사용자가 입력한 임의 검색어는 저장하지 않는다.

## 상태

`discovered → reviewing → source_confirmed → calendar_linked`

- `dismissed`: 관리자가 제외 이유를 남긴 후보
- `expired`: 검토되지 않은 채 보존기간이 지난 후보
- `source_confirmed`: 관리자가 원출처를 다시 확인한 후보
- `calendar_linked`: 확인된 후보를 편집 캘린더에 한 번 연결한 상태

`source_confirmed`는 곧 발행 가능하다는 뜻이 아니다. 2차 출처만 있는 편집 글은 기존 정책에 따라 승인이 차단되고, 공식·1차·AthleteTime 근거가 추가되어야 한다.

## 실행과 비용

- `NAVER_NEWS_COLLECTOR_ENABLED=false`가 기본값이다.
- 첫 14일은 관리자 수동 실행만 허용한다.
- 하루 40회, 월 800회 자체 한도를 넘기지 않는다.
- 401, 403, 429는 재시도하지 않는다.
- timeout과 5xx만 예산 안에서 한 번 재시도한다.
- 월별 화면은 매일 저장한 metadata를 집계하며 월말 대량 재수집을 하지 않는다.

## 보존

- 제외·만료 후보는 90일 뒤 삭제한다.
- 원출처 확인·편성 후보는 연결된 감사 기록이 유지되는 동안 보존한다.
- 실행 집계는 13개월 보존한다.

## 활성화 게이트

14일 동안 credential 누출, 중복 insert, 승인 없는 편성·발행, 호출 예산 초과가 모두 0이어야 예약 수집을 검토한다. 자동 예약은 소유자의 별도 `GO-DAILY` 승인 전까지 켜지 않는다.
