# 페르소나 검증에 따른 팀 성과판과 개인 메모 경계

상태: 구현 전 결정·검증 기준

이 문서는 학생 선수, 대학 팀 주장, 실업팀 코치, 보호자, 운영자, 공용 기기
사용자, 접근성 사용자, 악의적 수집 시도자를 기준으로 작성했다. 제품 기능을
추가하거나 공개 범위를 바꾸지 않는다.

## 한 줄 원칙

팀 화면은 공개 경기 결과 범위에서 보는 **시즌 성과판**이고, 개인 메모는
검색·공유·팀 통계와 절대 섞이지 않는 **계정 소유의 비공개 보관함**이다.

## 확인된 현재 경계

1. 팀 공개 DTO에는 `name`, `athleteKey`, `records`, `affiliations`,
   `workspace`, `note`, `attachment`, `sourceId`가 없어야 한다. 이 경계는
   `backend/tests/team-public-dto-boundary.test.js`가 재귀 검사한다.
2. 팀 검색은 개인 선수 목록으로 이어지지 않고, 팀 통계 페이지는 개인 기록을
   나열하지 않는다는 문구와 계약을 이미 가진다.
3. 기존 `/api/upload/*`는 공개 Cloudinary 주소를 반환하는 업로드 경로다.
   개인 메모 사진이나 첨부파일에 재사용하면 안 된다.
4. 동명이인과 소속 변경은 자동으로 합치지 않는다. 팀 통계도 소속명 변경·합병을
   자동으로 같은 팀으로 통합하지 않는다.

## 페르소나가 요구한 화면 기준

### 팀 주장과 코치

첫 화면은 최신 시즌을 기본으로 열고, 다음 네 수치만 먼저 보여 준다.

1. 대회 참가: 색인된 결과가 있는 고유 대회 수
2. 입상 기록: 등수 1~3이 확인된 결과 수
3. 기록 개선 확인: 같은 공개 선수 조각과 종목 안에서 비교 가능한 이전 기록보다
   좋아진 결과 수
4. 종목 수: 해당 범위의 고유 종목 수

`참가 선수 수`는 공식 재적 인원처럼 보일 수 있으므로 주 지표가 아니다. 표시가
필요하면 반드시 `이 사이트가 모은 기록에 나타난 선수 수`로만 표현한다.

그래프는 개인 최고 기록이나 개인별 향상 순위를 보여 주지 않는다. 대신 종목별
참가 비중, 대회 또는 월별 결과 수, 시즌별 네 지표 변화를 사용한다. 모든 차트
바로 아래에는 자료 기준 기간, 마지막 자료 날짜, 모은 공개 기록 기준, 누락 가능성을
짧게 둔다.

팀 화면에서 개인 기록으로 넘어갈 때는 팀 문맥을 전달하지 않는 빈 검색 화면을
연다. 버튼 문구는 `개인 기록 찾기`로 하고, 이름과 당시 소속을 함께 입력하라고
안내한다.

### 학생 선수와 공용 기기 사용자

한 화면에서는 하나의 결정을 요구한다. 긴 설명은 접고, 선택 전에는 이름, 당시
소속, 확인 기간, 종목, 출처 범위만 보여 준다. `내 기록`은 본인 인증이 아니라
이 기기에 저장한 선택이라는 문구를 유지한다. 브라우저 저장이 막히면 휘발성
상태와 다시 찾기 행동을 즉시 보여 준다.

### 보호자와 악의적 수집 시도자

팀의 `시즌 x 종목 x 성별/부문` 세부 그룹이 소수이면 개인 재식별 위험이 있다.
소수 그룹의 숫자, 차트 점, 정렬 힌트는 서버에서 함께 숨겨야 하며, 화면만 가리는
방식은 허용하지 않는다. 팀 API와 개인 보관함 사이의 조인은 금지한다.

## 구현 전 소유자 결정

다음은 데이터 공개 범위를 실제로 바꾸므로 코드보다 먼저 소유자가 정한다.

| 결정 | 권장 기본값 | 결정하지 않은 동안의 동작 |
| --- | --- | --- |
| 소수 집단 기준 | 고유 선수 5명 미만 세부 교차 집계 숨김 | 현재 공개 수치와 API를 확대하지 않는다. |
| 전체 팀의 선수 수 | 주 지표에서 제외 | 대회·입상·개선·종목 네 지표만 사용한다. |
| 개인 메모 저장 위치 | 계정 소유 private storage와 서버 권한 검사 | 사진·첨부파일 기능을 만들지 않는다. |
| 개인 메모 보존·삭제 | 사용자가 삭제하면 접근 불가, 백업·보존 기간은 별도 고지 | 서버 저장을 시작하지 않는다. |
| 미성년자 팀 통계 | 기본적으로 더 넓은 집계만 노출 | 개인별 최고·향상·명단 기능을 추가하지 않는다. |

### 운영 화면 확인 기록 (2026-08-10)

운영 팀 검색과 상세 화면을 직접 확인했다. 팀 화면에는 개인 이름, 공개 선수 키,
원본 행, 개인 보관함 내용이 보이지 않았고, 콘솔 오류도 없었다. 그러나 자료가 매우
적은 학교·팀에서도 `대회 1개`, `종목 1개`, `기록 1건` 같은 요약 수치는 현재
노출된다. 이 사실은 소수 집계 공개를 승인한 것이 아니다.

따라서 다음 구현에서는 화면에서만 숫자를 숨기는 방식이 아니라, 소수 교차 집계의
값·차트 점·정렬 힌트를 서버 공개 DTO에서 함께 제거해야 한다. 최소 인원 기준과
어떤 차원을 교차 집계로 볼지는 위 소유자 결정이 끝날 때까지 확정하지 않는다.

## 안전한 구현 순서

### 단계 0. 이미 가능한 검증 강화

- 팀 공개 응답을 재귀 검사해 금지 필드가 없는지 확인한다.
- 375px에서 팀 검색 → 최신 시즌 성과판을 세 번의 탭 안에 확인하는 E2E를 둔다.
- 팀 화면에서 개인 검색으로 이동할 때 팀 키, 후보 선택, 개인 보관함 상태가 URL과
  브라우저 저장소에 남지 않는지 확인한다.
- 팀 API 오류에 원본 파일 경로, 내부 키, 운영 메모가 섞이지 않는지 확인한다.

### 단계 1. 소수 집단 기준 결정 후 팀 성과판 정비

- 서버 공개 DTO에서 최소 인원 기준을 강제한다. 숨김은 숫자·차트·정렬 정보를
  함께 제거해야 한다.
- 계주, 단계가 불명확한 입상, 보류 원본은 네 지표에서 제외하거나 `확인 중`으로
  분리한다.
- 고정 데이터로 대회 수, 확정 1~3위, 비교 가능한 개선, 종목 수가 정확히 일치하는
  계약 테스트를 추가한다.

### 단계 2. 개인 메모를 시작하기 전의 필수 설계

- `/api/upload/*`와 분리된 인증 전용 API와 private object storage를 사용한다.
- 목록 API는 제목·수정 시각 등 최소 메타데이터만, 본문·사진은 소유자만 읽을 수
  있는 별도 요청으로 분리한다.
- 다른 계정의 요청에는 존재 여부를 알리지 않는 `404`만 반환한다.
- 운영자 도구에는 메모 본문, 사진, 다운로드 URL을 넣지 않는다.
- 로그인 해제, 계정 삭제, 비밀번호 재설정, 공유 기기에서의 세션 종료를 포함한
  삭제·접근 회수 테스트를 통과한 뒤에만 공개한다.

## 배포 차단 항목

채팅 신고 테이블 이전 PR #82는 아직 병합하거나 운영 DB에 실행하면 안 된다. 이미
기록된 이전 마이그레이션을 건너뛰는 경우 새 `reports` 테이블이 만들어지지 않을 수
있으며, 알려지지 않은 기존 테이블 모양도 fail-closed로 거부하지 못한다. 자세한
재현 조건과 필수 PostgreSQL 검증은 PR #82 검토 코멘트에 기록한다.

### 신고 테이블 이전을 다시 열기 위한 최소 증거

이전 파일을 고치거나 운영 DB에서 시험하지 않는다. 복구는 `migration-007-chat.sql`
체크섬을 유지한 **새 이력 파일**로만 한다. 그 이력 파일은 현재 스키마를 명시해
조회·변경하고, 다음 경우를 disposable PostgreSQL에서 실제로 통과해야 한다.

1. 기존 커뮤니티 `reports` 표를 보존한 뒤 새 채팅 신고 표를 만든다.
2. `007`이 이미 이력 장부에 기록됐지만 표가 옛 모양인 배포 상태를 복구한다.
3. `reports` 표가 없는 새 DB와, 이미 완전한 채팅 신고 표인 DB를 모두 그대로
   통과시킨다.
4. `target_type`만 있는 부분 채팅 표 또는 열·제약이 다른 알 수 없는 표는 어떤
   이름 변경도 하지 않고 실패한다.
5. `legacy_community_reports` 백업 표나 다른 스키마의 같은 이름 표가 이미 있을 때
   원본·백업·이력 장부를 모두 그대로 둔 채 실패한다.
6. 옛 표와 새 표의 `id` 기본값·시퀀스·기본키가 각각 독립적으로 동작하며, 채팅
   신고 작성과 운영자 조회 SQL까지 실행된다.

각 실패는 단일 트랜잭션 롤백 뒤 `reports` 원본 이름·행, 백업 표, 이력 장부가
변하지 않았음을 검증한다. 이 증거가 없는 상태에서는 `DATABASE_URL`을 사용한
명령이나 Render 운영 환경에서의 이전을 실행하지 않는다.

## 완료 조건

1. 팀 공개 API 응답에서 금지 필드가 0개다.
2. 소수 집단 규칙이 서버에서 강제되고, 숨겨진 그룹은 역추론 가능한 차트·정렬
   정보도 남기지 않는다.
3. 팀 화면은 개인 목록이나 개인 보관함으로 연결되지 않는다.
4. 개인 메모는 공개 업로드 URL, 검색 인덱스, 팀 통계, 관리자 화면 어디에도
   나타나지 않는다.
5. 모바일, 키보드, 저장소 차단, 느린 네트워크의 실제 브라우저 검증이 통과한다.
6. 데이터베이스 이전은 disposable PostgreSQL에서 recorded-migration,
   unknown-schema, backup-exists, schema-decoy 사례를 모두 통과하기 전에는
   운영 실행 대상이 아니다.
