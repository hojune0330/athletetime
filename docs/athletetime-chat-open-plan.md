# Historical: AthleteTime 공개 채팅 보류 기록

> **상태**: 보류. 이 문서는 2026-07-26의 과거 설계 기록이며 현재 출시 지시나 구현 명세가 아니다.
> **현재 기준**: 공개 채팅, `/api/chat/*`, `/ws/chat`은 모두 준비 중으로 닫혀 있다.
> **운영 확인**: 공개 화면은 준비 페이지여야 하며, 직접 HTTP·웹소켓 요청은 `503`과 `no-store`로 거절돼야 한다.

## 왜 보류했나

기존 설계는 브라우저가 만든 식별값과 신고 키를 서버가 신뢰했다. 이 구조에서는 한 사람이 값을 바꿔 여러 신고자인 것처럼 보이게 하거나 다른 이용자인 것처럼 메시지를 보낼 수 있다. 공개 기록 서비스에 필요한 신뢰 기준을 충족하지 못하므로, 화면을 숨기는 수준이 아니라 API와 웹소켓까지 닫았다.

## 재개 전 필수 승인 조건

다음은 별도 설계·구현·공격 테스트·운영자 승인을 모두 마친 뒤에만 새 문서에서 결정한다.

1. 서버가 발급하고 검증하는 세션 기반의 작성자·신고자 식별
2. 허용 Origin, 연결·발신 속도, 메시지 길이·형식의 서버 강제
3. 신고·블라인드·제재의 악용 방지와 감사 가능한 운영 흐름
4. 보존 기간, 삭제·열람 요청, 미성년자 보호, 운영자 권한 정책
5. 다계정·키 변조·대량 접속을 포함한 회귀·침투 테스트

새 구현은 이 문서를 되살리거나 환경변수를 추가하는 방식으로 진행하지 않는다. 재개가 승인되면 새 설계 문서와 별도 배포 게이트를 만든다.

## 보존한 교훈

- 익명성은 브라우저 저장값이 아니라 서버 검증과 운영 제한을 함께 갖춰야 한다.
- “신고 3회” 같은 자동 규칙은 신고자 고유성 및 조작 방지가 먼저다.
- 준비 중 기능은 메뉴만 감추지 않고 화면, HTTP API, 웹소켓을 모두 닫아야 한다.
- 개발용 검증 스크립트도 운영에 쓰기 전에 현재 공개 범위와 일치하는지 확인해야 한다.
